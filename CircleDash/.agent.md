# CircleDash project memory

This repo is a Unity rhythm-game project. Most gameplay logic sits under `Assets/New Engine` and the main systems are centered around beat timing, arrow generation, scoring, custom audio map analysis, and pause/settings screens.

## Core gameplay systems

- `Assets/New Engine/Rhythm/RhythmEngine.cs`
  - Main beat-timing engine.
  - Calculates interval length from BPM and step count.
  - Fires `OnBitEvent`, `OnBetweenBit`, and `OnSongEndEvent` based on audio timing.
  - Tracks `accuracy` and `boolOnBit` for hit quality.
  - Applies latency offset and ends the song when time exceeds duration.

- `Assets/New Engine/Rhythm/RhythmManager.cs`
  - Controls full-speed sections during the song.
  - Reads `X2_Sections` and triggers `ArrowGenerator.FullSpeed` around section boundaries.
  - Uses beat timing to delay speed changes by a few beats.

- `Assets/New Engine/arrow/ArrowGenerator.cs`
  - Creates incoming arrows on beat events.
  - Generates directional patterns and instantiates arrow prefabs.
  - Uses `FullSpeed` to spawn a denser pattern during active speed sections.

- `Assets/New Engine/arrow/ArrowProperties.cs`
  - Stores arrow direction, hit state, color, and lifetime behavior.
  - Tracks whether an arrow is hittable and handles skip/miss behavior.

- `Assets/New Engine/arrow/CurrentArrowManager.cs`
  - Keeps the currently active arrow and updates the hit target.
  - Connects hit detection to the arrow that is currently in play.

- `Assets/New Engine/arrow/RhythmMoving.cs`
  - Moves arrows toward the hit plate based on rhythm timing.
  - Likely controls arrow travel speed and visual movement.

## Hit and scoring systems

- `Assets/New Engine/HitManagers/HitManager.cs`
  - Main hit-resolution controller.
  - Reacts to joystick input, validates hit timing, determines success or miss.
  - Awards score, combo, grade, particle effects, and sound feedback.
  - Uses `RhythmEngine.accuracy` to judge quality.

- `Assets/New Engine/HitManagers/Combo.cs`
  - Tracks combo count and multiplier.
  - Updates UI text and resets when a miss occurs.
  - Restores life occasionally on combo milestones.

- `Assets/New Engine/HitManagers/Score.cs`
  - Stores current score and animates the on-screen score display.
  - Uses a smooth increment effect for UI feedback.

- `Assets/New Engine/HitManagers/Lives.cs`
  - Tracks player lives and triggers lose condition at zero.
  - Updates visual life indicators by toggling animator states.

- `Assets/New Engine/HitManagers/GradesManager.cs`
  - Spawns Perfect / Good / Miss grade floating effects.
  - Tracks counts for end-of-run results.

## Custom map and audio loading

- `Assets/New Engine/Maps/CustomMapManager.cs`
  - File picker for custom songs.
  - Loads audio from the device and stores it in `LoadedClip`.
  - Requests file permission and shows error UI on invalid files.
  - Sets `PauseManager.needToAnalyseMap` before loading the gameplay scene.

- `Assets/New Engine/WinLosePause/PauseManager.cs`
  - Initializes song analysis for custom maps.
  - Reads `LoadedClip`, analyizes BPM and sections, then applies results to the rhythm engine.
  - Handles pause, resume, restart, menu transitions, and scene loading.

- `Assets/New Engine/Rhythm/Test/MusicAnalyser.cs`
  - Audio-analysis logic for breaking a track into rhythm sections.
  - Provides section timing data the gameplay systems use for speed phases.

- `Assets/New Engine/Rhythm/Test/UniBpmAnalyzer.cs`
  - BPM estimation utility for imported audio.

- `Assets/New Engine/AudioManager.cs`
  - Configures Unity audio DSP buffer size for smoother playback.

## Working rules for this project

- Prefer reading the gameplay chain together: `RhythmEngine` -> `ArrowGenerator` -> `CurrentArrowManager` -> `HitManager`.
- When editing custom-map logic, also check `CustomMapManager` and `PauseManager` together, because they share static state.
- Preserve static state carefully: `Score`, `Combo`, `Lives`, `RhythmEngine.accuracy`, and `PauseManager.needToAnalyseMap` are used across scenes.
- Most gameplay logic is event-driven, so new code should follow the current Unity event patterns instead of introducing a parallel system.
- UI and persistence scripts normally use `Application.persistentDataPath` for save files and `SceneManager` transitions for flow control.

## Good default fix strategy

1. Start from the beat/timing engine.
2. Confirm the event flow and static state used by the affected system.
3. Change the smallest relevant file, then validate with Unity play mode or compile checks.
4. Keep naming consistent with the current codebase, especially for `OnBitEvent`, `OnSongEndEvent`, and `accuracy`/`latency` data.
